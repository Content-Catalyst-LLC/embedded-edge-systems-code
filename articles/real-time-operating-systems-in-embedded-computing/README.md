# Real-Time Operating Systems in Embedded Computing

This companion directory supports the article **Real-Time Operating Systems in Embedded Computing**.

It treats RTOS design as a structured timing architecture: task models, priorities, periods, deadlines, worst-case execution time, response time, blocking, interrupt latency, deferred work, queue pressure, stack evidence, power coordination, tickless idle, runtime tracing, and field telemetry.

Engineering focus:

- task manifests and timing contracts
- priority assignment and schedulability analysis
- hard, firm, soft, and best-effort task classification
- worst-case execution time, deadlines, response time, jitter, and slack margin
- ISR duration, interrupt latency, and deferred work boundaries
- synchronization, lock ordering, blocking, and priority inversion
- queue high-water marks, producer/consumer pressure, and stale-data policy
- stack watermarks, bounded allocation, and memory footprint control
- tickless idle, idle residency, timer wakeups, and low-power coordination
- runtime tracing, deadline-miss telemetry, watchdog evidence, and fleet reporting
- systems-code scaffolding in C, C++, Rust, Go, MicroPython, TinyML, PYNQ, and HDL
